## Remaining concrete mapping requirement

The released planner compares source/type/policy/location/proof fields; it does not compare `content_sha256`. Current inventory/converter code supplies the controlled declaration fields but leaves nondeclaration objects with fewer controlled fields. Thus a final changed gate, source-row or audit object must not be silently called identical merely because it shares a concept key and PDF hash with the inspection origin.

The new emitter fails closed when one nondeclaration concept groups differing content hashes. Root can explicitly assign separate provenance-variant concepts through `provenance_concept_overrides`, preserving the common `stable_key` association and every origin occurrence, without asserting equivalence. Alternatively a separately reviewed additive converter can attach substantive nondeclaration policy/content fields. No released change is needed. All baseline paired contents here are actually equal, so the draft itself passes this guard. Actual final collisions and affected-book decisions remain root work.

## Input schema and exact execution order

`prepare_mapping_catalogue.py --root R --spec FILE --spec-sha256 SHA --output NEW.json` accepts:

- `schema: 1`; `stage: baseline-draft` or `final-origin-review-draft`; `merge_lane`; and `final_committed_head` (null for a baseline draft, the explicit exact merge-origin head for a final draft).
- Exactly two `lanes`, each with `lane_id`, hash-pinned `inventory`, hash-pinned `context`, and the exact ordered `fingerprints` reference list recorded in that origin inventory.
- Optional `declaration_overrides` with declaration, explicit concept ID, producer payload and policy payload references. Exact producer identity must match the native record. This packet uses only the two frozen Eq1.3 overrides.
- Optional `provenance_concept_overrides` with lane ID, nondeclaration kind, stable key and explicit concept ID. Unused, duplicate or declaration-kind entries are rejected.

Every reference is `{path, sha256}`, with a normalized repository-relative path. The final merge inventory must itself have `require_closed=true`, no open rows and the exact supplied final head. No missing native record is inferred from Lean source text. Inventory generation remains the existing POSIX helper's responsibility; this pure helper checks hash-bound inputs and exact identities, not live Git.

Root reviews the complete proposal before using `emit_reviewed_mapping.py`. A separately supplied review must have `schema:1`, `status:reviewed-for-structural-preparation`, `source_acceptance:false`, substantive `review` text, nonempty bound `evidence`, and `mapping_semantics_sha256`. That digest covers every lane/kind/stable-key/concept/disposition and declaration producer/policy choice. It deliberately excludes commit-dependent occurrence IDs: review evidence must be committed in the candidate, so binding its own eventual commit would create a hash cycle. Final origin/head/content identities are independently bound by final inventories and the existing converter. The generated `mapping-review-surface.json` is awaiting review, not such a review record.

Before constructing the final candidate, root may run emitter mode `payloads` with `--root R --spec FILE --spec-sha256 SHA --output NEW_DIRECTORY`. Its spec contains hash-pinned `catalogue` and externally reviewed `review`. It exclusively materializes the reviewed producer/policy objects and a `payload-files.json` map. Root commits the actual source, review and payloads; then refreshes final inventories after the final commit. No emitted payload file itself asserts acceptance.

After the released launcher records the real candidate, emitter mode `mapping` takes the same flags with a fresh output file. Its spec also needs exact `topology`, `request`, `status`, `epoch_schema` and `payload_files` references. It requires the final closed-origin catalogue, prepare/forbid/none, one merge and one inspection lane with exact frozen commits, matching request/topology/status, and every required payload already present. It emits only the existing version-2 mapping schema, never a candidate or epoch. A baseline catalogue is rejected even with a supplied review. Root then runs the unchanged two-lane converter, which checks candidate Git bytes including that review and every payload.

Finally root supplies actual collisions/transports, affected-book verdicts, measured organization/debt evidence and all eight candidate-tree receipts, then runs the released pristine verifier. The receipt order remains source coverage, import graph, signature graph, body graph, declaration resolution, focused build, full build, pristine replay. This packet does not fabricate any of them and does not create integration or promotion authority.
